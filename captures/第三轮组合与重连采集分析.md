# TourBox Lite 第三轮：组合输入与串口重开

证据：[配置后的组合日志](serial-session-20261117-221137-082372.jsonl)、[不拔USB重开串口日志](serial-session-20261117-221234-063936.jsonl)。与前两轮合并后的事实见 [实测profile](tourbox-lite-observed-profile.json)。

## 1. 组合输入

| 操作 | 实际字节顺序 | 结论 |
| --- | --- | --- |
| 按住Tall，旋钮顺/逆时针，释放Tall | `00 → 44×6 → 04×6 → 80` | 原始按钮和旋转码分别上报 |
| 按住Top，滚轮上/下，释放Top | `02 → 49×8 → 09×9 → 82` | 原始按钮和旋转码分别上报 |

这两种组合没有新组合码，没有旋转停止码。按下/释放成对且顺序正确；本轮共29个旋转步进、4个按钮事件，加26字节解锁回复，共59字节RX。

网关应保留字节顺序；电脑端根据当前按钮按住状态处理组合。无需把Tall+旋钮或Top+滚轮重新编码成特殊报文，也不能在释放前丢掉任一旋转事件。其他修饰键和多按钮组合还未逐一实测。

## 2. 不拔USB重开串口

按本次测试流程，上一会话退出后保持USB连接及Console退出，再打开新的capture会话：

1. 再次发送解锁，收到26字节回复。
2. **重新发送配置之前**，旋钮顺时针已输出11个`44`。
3. 重发相同94字节配置后，旋钮顺时针继续输出11个`44`。

本轮共48字节RX，包括26字节解锁回复和22个旋转步进。没有专门配置ACK、未知码或错误日志。

这证明本次串口关闭/重开流程没有清掉已有旋转配置，重复解锁和重发已测配置在本轮可用。它不证明配置跨断电持久化，也不代替ESP32 CDC handle关闭/重开或BLE重连的实机测试。

## 3. 解锁回复与初始化规则

目前四个会话的26字节解锁回复完全相同，详见profile的四条样本。字段含义仍未解码，不能假定永远固定或在固件中伪造它。

实现采用明确规则：

- 冷启动、VBUS断电复位或设备状态未知时，使用完整的“解锁→已测94字节配置”初始化。
- 已配置设备在本次同次上电串口重开后可继续旋转；为避免依赖残留状态，新会话仍可以由电脑端按完整序列初始化，重复配置本轮已验证不影响输出。
- BLE断开首先清理网关队列、订阅、事务和按键状态，不默认对USB设备断电。只有USB错误或实机证明软件恢复不可用时才考虑受控VBUS复位。
- 正常BLE桥接初始化仍由电脑端发起；网关不额外抢先发送第二套解锁/配置。

## 4. 当前采集完成范围

电脑端基础协议采集已完成：USB身份和端点、可用串口设置、解锁回复、默认配置效果、8个按钮、4个旋转方向、两种组合，以及同次上电串口重开。

这些足以形成ESP32 USB诊断固件的第一版实物profile。后续重点转为ESP32 USB Host及BLE运行验证；官方Console无线协议、供电电流、控制线必要性、初始化最短等待时间、更多组合和长期稳定性仍未完成。
